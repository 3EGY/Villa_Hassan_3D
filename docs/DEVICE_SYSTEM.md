# Villa Hassan — نظام إدارة الأجهزة (Device Registry) | v2.8

> **الوضع الحالي: محاكاة داخل المتصفح فقط.** لا يوجد ربط فعلي بأي جهاز في الفيلا. تعمل نفس واجهة v2.6، وأصبحت جميع اللمبات الـ14 مُسجلة في مركز واحد. أُضيفت في v2.8 محاكاة 5 شترات و5 ستائر، ثم ستارة الصالة في v3.0 ليصبح الإجمالي 6 ستائر؛ انظر [تفاصيل التوزيع والتحكم](COVERINGS_AND_VOICE.md).

## لماذا أضفنا هذه الطبقة؟

المشكلة القديمة: اللمبات مرتبطة مباشرة بمكونات Three.js وبواجهات التحكم؛ لو أضفنا ستائر أو سماعات بالأسلوب نفسه فسيتكرر المنطق وتتداخل بيانات الأجهزة مع تفاصيل المشهد. يقدّم `window.VillaDevices` جدولًا واحدًا للأجهزة، وواجهة موحدة للاستعلام وإرسال الأوامر، وإشعارات تغيّر الحالة.

```text
زر المستخدم / قائمة الغرفة / مشهد 3D
                │
                ▼
       VillaDevices Registry
          │          │
  التعريفات والحالات  توجيه الأوامر
                     │
                     ▼
             Adapter لكل نوع
             │           │
      محاكاة الآن    ربط حقيقي لاحقًا
             │
       تحديث شكل 3D
```

## الملفات الجديدة

| الملف | الغرض |
| --- | --- |
| `js/devices/registry.js` | سجل مركزي للأجهزة، بحث بحسب الغرفة والنوع، بث تغيّر الحالة، وتوجيه الأوامر |
| `js/devices/lighting/adapter.js` | ربط الـ14 لمبة الموجودة بالفعل بالسجل، وتنفيذ أوامر الإضاءة باستخدام كودها القديم |
| `scripts/test-devices.mjs` | اختبارات تلقائية للمسارات المنطقية ومرونة البيانات |
| `docs/DEVICE_SYSTEM.md` | هذا الدليل |

**لم نكرر تعريف اللمبات:** لا تزال إحداثياتها وخاماتها في `js/devices/lighting/fixtures.js`. عند تجهيز المجسم يسجل `VillaLightingAdapter.registerLights()` اللمبات كما هي، وتقوم `applySmartLightState()` بنشر أي تغيير إلى السجل حتى لو جاء من القائمة القديمة أو أوضاع الإضاءة.

## سجل الجهاز

```js
{
  id: 'bulb_living',                  // ثابت، وفريد على مستوى الفيلا
  floorId: 'floor1',                 // يسهل إضافة أدوار أخرى لاحقًا
  zoneId: 'livingRoom',              // من ZONE_SPECS — ليس 'overview'
  kind: 'light',                     // light | curtain | shutter | speaker ...
  name: 'ثريا الصالة العائلية',
  capabilities: [
    'turnOn', 'turnOff', 'toggle',
    'setBrightness', 'setColor', 'setTimer'
  ],
  state: {
    on: true,
    brightness: 90,                 // 0 .. 100
    color: '#ffb454',
    timerMinutes: 0                 // إعداد المؤقت، وليس الوقت المتبقي
  },
  mode: 'simulation'                 // لم تتم إضافة hardware adapter
}
```

### استخدام السجل من كود التطبيق أو Developer Tools

بعد الضغط على «ابدأ الجولة»، يمكن تجربة ما يلي في Console المتصفح:

```js
// عرض الأجهزة التي أصبحت مسجلة
VillaDevices.list();

// أجهزة غرفة معينة
VillaDevices.list({ zoneId: 'masterBedroom' });

// نتيجة معزولة (copy) لا تسمح بتعديل الحالة الأصلية بالخطأ
VillaDevices.get('bulb_living');

// إصدار أمر موحد — يُنفذ عبر Lighting Adapter
await VillaDevices.execute('bulb_living', 'setBrightness', 50);
await VillaDevices.execute('bulb_living', 'setColor', '#38bdf8');
await VillaDevices.execute('bulb_living', 'turnOff');

// استقبال الأحداث، وإيقاف الاستماع عند الحاجة
const unsubscribe = VillaDevices.subscribe(({ type, device }) => {
  console.log(type, device.id, device.state);
});
unsubscribe();
```

العمليات المتاحة حاليًا للإضاءة: `turnOn`, `turnOff`, `toggle`, `setBrightness` (0..100), `setColor` (#RRGGBB), `setTimer` (عدد دقائق صحيح من 0 إلى 120). لا يُرسل أي أمر إلى الشبكة.

## إضافة ستارة أو شتر لاحقًا (دليل تأسيسي سابق من v2.7)

أصبحت الخطوات التالية مطبقة في مجلد `js/devices/coverings/`؛ الخطوات مرجع للتوسعات القادمة:

1. سجّل الجهاز في ملف بيانات مستقل داخل `js/devices/curtains/` أو `js/devices/shutters/`، مع `id` ثابت، `zoneId` من الغرف المعروفة، و`windowId` مرجعي عند ارتباطه بشباك. **أسماء الشبابيك موجودة في** `js/data/window-config.js` (`W1-W2`, `W3`, `W4`, `W5`, `W6`, `W7`). لا يعني وجود شباك أنه مزود بستارة أو شتر.
2. اجعل قدرة الجهاز `open`, `close`, `setPosition`، ثم اعتمد معنى النسبة (اقتراح: `0` مغلق بالكامل، `100` مفتوح بالكامل). **لا تعتمد هذه القيم قبل تحديد نوع الموتور وتوجه الحركة.**
3. أضف Adapter في ملف منفصل، واستخدم `VillaDevices.registerAdapter(kind, { execute(...) { ... } })` لتنفيذ الأمر وتأكيد الحالة بـ `context.reportState({ position: ... })`.
4. أضف مؤثرات المجسم في ملف `scene` من دون أي اتصال مباشر بالشبكة، وأضف الواجهة (أزرار وشريط نسبة الفتح) مع استعلام الأجهزة باستخدام `VillaDevices.list({ zoneId })`.
5. اختبر إضاءة الغرف والشبابيك والهواتف كما كانت في النسخة السابقة؛ لا تغيّر كودها لأجل النوع الجديد.

مثال **افتراضي للتوثيق فقط**، ليس جهازًا موجودًا في الفيلا:

```js
VillaDevices.register({
  id: 'f1_living_curtain_01',
  floorId: 'floor1',
  zoneId: 'livingRoom',
  kind: 'curtain',
  name: 'ستارة توضيحية',
  capabilities: ['open', 'close', 'setPosition'],
  initialState: { position: 0 }
});
```

## السماعات والربط الحقيقي

نفس المسار ينطبق على `speaker` (حالة التشغيل، الصوت، المنطقة، الأوامر). يجب إبقاء مشغل الصوت أو التكامل الخارجي منفصلًا عن الغرف والمجسم.

عند إضافة أجهزة حقيقية سنحتاج خادمًا موثوقًا داخل الشبكة أو بوابة تحكم مناسبة، ودعم المصادقة والاتصال الآمن ومزامنة الحالة والأعطال. **GitHub Pages موقع ثابت، وليس خادمًا آمنًا للأجهزة المنزلية.** لا تنشر مفاتيح API أو توكنات أو عناوين أجهزة حساسة في ملفات الواجهة. `VillaDevices.execute` ينتظر نتيجة الـAdapter ولا يفترض نجاح الجهاز فعليًا إلا بعد تقرير الحالة منه.

## نتائج التحقق لهذا الإصدار

```bash
node scripts/check-project.mjs
node scripts/test-devices.mjs
```

تتحقق الاختبارات من تعريف الأجهزة، ومعرفاتها الفريدة، وأسماء الغرف، وعدم تسرّب الحالة، وتنفيذ الأوامر، والتزامن مع التحكم السابق. كما أُجري اختبار DOM بمتصفح Headless (مع Renderer بديل عن WebGL)، وأكد تسجيل 14 لمبة، وتطبيق وضع النوم وإغلاق الكل وتعديل الشدة عبر السجل دون أخطاء JavaScript. اختبار العرض الحقيقي داخل WebGL يبقى على المستخدم بعد النشر، كما في النسخة السابقة.
