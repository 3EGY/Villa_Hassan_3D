# دليل هيكل مشروع Villa Hassan Smart Home — v2.8

> **النطاق الحالي:** نموذج تجريبي للدور الأول؛ 14 إضاءة + 5 شترات + 6 ستائر محاكاة مسجّلة في `VillaDevices`، 14 منطقة في قائمة البيانات (تشمل `overview`)، و6 شبابيك معتمدة. **لا يوجد ربط فعلي** بأي تجهيزات داخل الفيلا حتى الآن؛ محاكاة الشتر والستائر مفعلة في v2.8.

**أساس v2.7:** تم تنفيذ سجل الأجهزة العام وAdapter الإضاءة. انظر **[الدليل الكامل للنظام](DEVICE_SYSTEM.md)** وطريقة اختبار أوامر الأجهزة. أضيف الشتر والستائر والمحاكاة المرئية في v2.8، انظر [دليل الشتر والصوت](COVERINGS_AND_VOICE.md).

## الفكرة الأساسية

أصبحت صفحات HTML مسؤولة عن ترتيب عناصر الواجهة وربط ملفاتها فقط. نُقلت الأكواد وCSS والمكتبات إلى ملفات ذات مسؤوليات محددة، وحُذفت صورة المخطط المضمنة في HTML وJavaScript واستُخدمت `assets/reference-plan.png` مباشرة.

لا توجد حاليًا خطوة بناء أو اعتماد على npm للتشغيل والنشر. ملفات JavaScript **كلاسيكية ومترابطة عبر نطاق المتصفح العام** (`global lexical scope`)، وليست ES Modules معزولة. السبب هو الحفاظ على جميع دوال `onclick` وسلوك النموذج الأصلي أثناء إعادة التنظيم. **ترتيب تحميل ملفات JS في `index.html` مهم**؛ لا تغيّره دون مراجعة الاعتماديات. يمكن الانتقال لاحقًا إلى ES Modules و`import/export` مع فصل حالة التطبيق وإلغاء معالجات الأحداث المضمنة، كتطوير مستقل.

## مسار التشغيل

1. في `<head>` تُحمَّل ملفات `vendor/` (Tailwind / Three.js / OrbitControls) وأنماط CSS.
2. بعد عناصر HTML تُحمَّل `js/data/window-config.js` ثم ملفات المشروع من **أعلى لأسفل حسب ترتيبها في `index.html`**.
3. ملف `js/core/bootstrap.js` يجهّز شاشة الترحيب ويستدعي `initScene()` بعد التحميل.
4. تبني `initScene()` النموذج، وتهيّئ الإضاءة والمُلصقات والتفاعل.
5. يستخدم التحكم اليدوي وأوضاع الإضاءة نفس `smartLights` الحالية، ويحدّث مشهد Three.js محليًا، كما ينشر أي تغيير إلى `VillaDevices`.
6. يستخدم محرر الشبابيك `js/windows/editor.js` في كلتا الصفحتين؛ وفي الصفحة الرئيسية يربطه `js/windows/viewer-bridge.js` بالمجسم.

## البيانات والمقاسات

- `js/data/window-config.js` هو **مرجع التشغيل** للشبابيك: مواقع الفتحات، العروض، مناسيب الجلسات، الارتفاعات المعتمدة، ومفتاح التخزين.
- `docs/WINDOW_SCHEDULE.json` **لقطة توثيقية** من المقاسات المعتمدة وليست مصدرًا يقرأه التطبيق. حدّثها أيضًا إذا صدر اعتماد جديد، ثم شغّل `node scripts/check-project.mjs` للتأكد من اتساق المقاسات.
- يظل `assets/reference-plan.png` المرجع البصري الوحيد لصورة المخطط في كلتا الصفحتين.
- `js/data/rooms-and-items.js` هو مرجع وصف الغرف وقطع الأثاث وزوايا الكاميرا الأساسية. انتبه إلى أن أزرار الغرف في `index.html` قد تحتاج تعديلًا إذا أضفت غرفة جديدة.

## كيف نضيف جهازًا جديدًا لاحقًا؟

**لا تضف منطق الجهاز مباشرة إلى `index.html` أو `js/scene/init.js`.** لقد أصبح `VillaDevices` وواجهة الـAdapters موجودَين بالفعل. لتوسيع الشتر والستائر الموجودين وإضافة السماعات لاحقًا، اتبع النمط التالي:

1. **تعريف الجهاز:** أنشئ ملف بيانات داخل `js/devices/<kind>/` يحتوي `id` ثابتًا، `zoneId`، نوع الجهاز، قدراته (`open`, `close`, `setPosition` أو `volume`, `play`, `pause`) وحالته الأولية.
2. **المحاكاة:** اكتب منطق تغيير الحالة الافتراضية في ملف `controller.js` مستقل عن واجهة المستخدم وعن مجسم Three.js.
3. **الواجهة:** ضع أزرار الجهاز وشريط التحكم في `js/ui/` أو في مجلد نوع الجهاز إن كانت واجهة خاصة به؛ تعمل على أي جهاز يُطابق القدرات لا على اسم غرفة ثابت.
4. **المشهد:** أضف تمثيله وتغيير حالته البصرية في ملف scene مستقل؛ لا تُدخل استدعاءات شبكة إلى وظائف بناء الحوائط أو الأثاث.
5. **التكامل الفعلي مستقبلًا:** اجعل واجهة التشغيل تتصل بخدمة موثوقة عبر Adapter منفصل، بدل إرسال أوامر مباشرة للأجهزة من المتصفح. يجب التعامل مع التأكيد، وفقدان الاتصال، والمزامنة بين الشاشات، والصلاحيات.
6. **الاختبار:** تأكد أن فشل الجهاز أو الشبكة لا يمنع عرض الفيلا ولا يوقف الإضاءة الحالية.

نموذج بيانات **مقترح للمستقبل وليس مطبّقًا في النسخة الحالية**:

```js
{
  id: 'floor1-living-curtain-01',
  kind: 'curtain',
  zoneId: 'livingRoom',
  capabilities: ['open', 'close', 'setPosition'],
  state: { position: 0, online: true }
}
```

تقسيم الأنواع المقترح عند الإضافة:

```text
js/devices/
  lighting/   ← موجود ويعمل الآن
  coverings/  ← موجود: الشتر والستائر والتوقيت والمجسم
  speakers/   ← يُنشأ عند التنفيذ
js/integrations/ ← يُنشأ بعد اختيار منصة التحكم الفعلية
```

**تنبيه أمني:** لا تضع مفاتيح أو كلمات مرور أو رموز دخول الأجهزة داخل ملفات الموقع الثابت أو على GitHub Pages. الربط الحقيقي يحتاج تحديد بروتوكول الأجهزة وحدود الشبكة وطريقة المصادقة أولًا.

## التشغيل والاختبار

لتجربة المشروع: افتح `index.html` بعد فك الضغط مع الاحتفاظ بالهيكل كاملًا، أو (الأفضل للتطوير) من جذر المجلد:

```powershell
py -m http.server 5500
```

ثم افتح `http://localhost:5500/` في متصفح يدعم WebGL. لا توجد حاجة إلى تثبيت مكتبات تشغيل خارجية. عند امتلاك Node.js، يمكن فحص المسارات وصحة JavaScript واتساق بيانات الشبابيك عبر:

```powershell
node scripts/check-project.mjs
```

افحص يدويًا: فتح الشاشة؛ الدخول للجولة؛ اختيار الغرف؛ تشغيل/إطفاء لمبة؛ تعديل الشدة واللون؛ المؤقت؛ أوضاع النوم/المعيشة/عدم التواجد/إغلاق الكل؛ النهار/الليل؛ إعدادات الطبقات؛ فتح محرر الشبابيك وحفظ قيمة؛ العمل على هاتف؛ وتصدير OBJ.

الاختبار الآلي السابق يراجع الملفات والبنية والبيانات؛ **ولا يحل محل اختبار العرض الحقيقي على متصفح يدعم WebGL**.

لفحص نظام الأجهزة الموحد شغّل أيضًا `node scripts/test-devices.mjs`.
